## 2. CI 게이트

| 검사 | R0 | R1 | R2+ |
|---|---|---|---|
| 포맷, 린트, 타입 | 해당 시 | 필수 | 필수 |
| 단위, 통합 | - | 필수 | 필수 |
| 핵심 E2E | - | 영향 시 | 필수 |
| 비밀, 의존성, SAST | 비밀 | 필수 | 필수 |
| 마이그레이션 앞·뒤 호환 | - | - | DB 변경 시 필수 |
| 리뷰 판정 | - | Claude 새 세션 1 | Claude 새 세션 1 + Codex 1 |
| 창업자 병합 확인 | P1 필수 | P1 필수 | 필수 |
| 패스키 동작 | `merge.confirm` | `merge.confirm` | `merge.r2` |

- PR 코드로 실행되는 CI에는 배포 비밀이 없다. `pull_request_target`에서 PR 코드를 실행하지 않는다.
- 외부 Action은 커밋 SHA로 고정한다. `GITHUB_TOKEN` 기본 권한은 읽기다.
- 저장소는 비공개 + Free다. GitHub 보호 규칙이 없으므로 [ADR-0009](adr/0009-private-free-merge-gate.md)의 병합 게이트를 쓴다.
- 에이전트와 `ax-core`는 GitHub 쓰기 자격증명이 없다. 창업자가 확인한 커밋만 권한 실행기가 병합한다.
- GitHub 서버는 직접 푸시를 막지 않는다. 감사가 원장에 없는 커밋을 찾아 멈추고, 배포 실행기가 그 커밋을 거부한다.
- 배포 비밀을 GitHub에 두지 않는다. 로컬 배포 실행기만 가진다.

## 3. 교차 리뷰

1. 리뷰어는 새 세션에서 패치, 수용 기준, 관련 파일만 받는다. `--resume`을 쓰지 않고 읽기 전용으로 실행한다. 실패하는 입력과 재현 방법을 찾도록 요청한다. 구현자의 설명과 상대 판정은 받지 않는다.
2. 코어가 판정을 [`review.schema.json`](schemas/review.schema.json)으로 검사한다.
3. 헤드 SHA가 다르거나 확인하지 않은 항목이 있으면 `pass`가 아니다.
4. R2는 서로 다른 공급자 2개가 필요하다. 하나는 구현 공급자와 달라야 한다.
5. 리뷰어가 없거나 한도가 끝나면 `blocked`다. Codex를 Claude로 대체하지 않는다. 구현과 다른 Claude 모델도 이기종으로 세지 않는다.
   Codex가 구현했다면 두 조건을 같은 방식으로 적용한다.
6. 발견에는 재현 방법이 필요하다. 구현자는 수정하거나 반증 시험을 낸다.
7. 리뷰어가 3회 안에 합의하지 못하면 창업자가 결정한다. `critical`과 `high`는 예외 승인이 없다. 수정하거나, 재현 시험으로 거짓 발견임을 보여야 한다.
   거짓 발견으로 닫을 때는 시험과 창업자 사유를 이벤트로 남긴다.
8. R0는 리뷰 0건을 요구한다. `reviewing`을 바로 통과한다.
9. 수정 뒤에는 두 리뷰어 모두 새 SHA를 다시 본다.

이기종 모델 합의도 결함 부재를 보장하지 않는다. 매월 심어 둔 결함 20건으로 탐지율을 잰다.

## 4. 시험 전략

- 변경 줄 커버리지 80% 이상. 생성 코드와 타입 선언은 제외 목록으로 관리한다.
- 인증, 결제, 권한, 상태 전이는 분기 100%와 실패 시나리오를 요구한다.
- 변이 시험은 핵심 모듈에서 주 1회 실행한다.
- 불안정 시험은 자동 재실행으로 통과시키지 않는다. 격리하면 만료일과 소유자를 기록한다. 핵심 경로 시험은 격리할 수 없다.
- 에이전트 평가는 고정 과제 30개로 시작한다. 모델, 프롬프트, Skill 변경 전후를 과제당 3회 비교한다. 이 표본은 큰 퇴행만 찾는다.

## 6. 사고 대응

| 등급 | 예 | 첫 행동 |
|---|---|---|
| SEV1 | 비밀 유출, 무단 결제·배포, 샌드박스 탈출 | `ax freeze`, 키 폐기, 실행기 중지 |
| SEV2 | 메모리 오염, Hook 생존 대조 실패 | `ax freeze`, 볼트 되돌리기 |
| SEV3 | 게이트 오작동 | 해당 프로파일 중지 |

`ax freeze`는 새 실행, 승인 소비, outbox를 멈추고 실행 중인 샌드박스를 끝낸다. 이미 배포된 서비스와 고객 청구기는 멈추지 않는다. 그것은 서비스별 런북으로 따로 멈춘다. 네트워크 없이 동작한다. 실행기는 멈춤 파일을 매번 확인한다.
순서는 차단, 증거 보존, 교체, 복구, 사후 기록이다. 개인정보 유출 신고 기한은 법률 전문가와 미리 확인해 런북에 적는다.
