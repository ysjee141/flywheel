# ADR-0009. 비공개 + Free에서는 AX 병합 게이트를 쓴다

상태: 요금제와 공개 여부는 창업자 결정 (2026-11-25). 게이트 구조는 제안

## 결정

저장소는 비공개, 요금제는 GitHub Free로 한다. GitHub의 보호 규칙 없이 다음 네 가지로 대신한다.

1. 에이전트와 `ax-core`에는 GitHub 쓰기 자격증명을 주지 않는다. 별도 봇 계정도 만들지 않는다.
2. 저장소 하나로 제한한 세분 토큰을 별도 OS 사용자 `ax-publish`가 가진다. 토큰에는 Workflows와 Administration 권한이 없다.
3. 권한 실행기의 게이트만 병합한다. 창업자는 P1의 모든 병합을 승인 페이지의 패스키로 확인한다([ADR-0011](0011-founder-console.md)).
4. 게이트는 병합한 커밋을 원장에 남긴다. 배포 실행기는 원장에 없는 커밋을 배포하지 않는다.

## 게이트 검사

- 승인한 헤드 SHA와 기준 SHA가 지금도 같다. 기준이 바뀌면 다시 검증한다.
- 지정한 GitHub Actions 워크플로가 그 헤드 SHA에서 성공했다. 검사 이름만 믿지 않는다.
- 위험도에 맞는 리뷰 판정과 창업자 확인이 그 헤드 SHA에 묶여 있다.
- 병합 API에 기대 헤드 SHA를 넘긴다. 병합 뒤 `main`의 트리가 검증한 트리와 같은지 확인한다.
- 워크플로 변경은 토큰으로 올릴 수 없다. 창업자가 GitHub 웹에서 R2 절차로 직접 반영하고 원장에 등록한다.

## 감사

`main`의 새 커밋과 강제 푸시를 원장과 비교한다. 병합과 배포 직전, 그리고 10분마다 한다.
원장에 없는 커밋이 있으면 `ax freeze`를 걸고 창업자에게 알린다.

## P1 게이트 구현 전

창업자가 GitHub 웹에서 위 검사를 확인표로 수행하고 직접 병합한다. 푸시는 창업자가 `ax-publish`로 한다.

## 이유

비공개 저장소의 보호 브랜치와 ruleset은 Pro 이상에서 제공된다([GitHub 문서](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches), 검색 요약으로 확인).

## 대가

GitHub 서버는 `main` 직접 푸시를 막지 않는다. 토큰이나 창업자 계정을 탈취당하면 게이트를 우회할 수 있다. 감사는 이를 막지 않고 발견하며, 배포를 막는다.

## 다시 검토할 조건

무인 실행이나 자동 병합을 열기 전, 협업자가 생길 때, GH-07 우회가 한 번이라도 발생할 때는 Pro로 올린다.
