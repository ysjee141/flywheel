# ADR-0012. 얇은 구축 하네스로 AX를 만든다

상태: 창업자 결정 (2026-11-25)

## 결정

분석, 설계, 구현, 검증, 리뷰, 병합, 회고를 `axb` 스크립트가 검사한다. 최소판으로 P0을 실행하고 P0 뒤에 보완한다.
창업자는 R2·설계 변경의 설계와 모든 병합을 확인한다. 하위 에이전트는 한 번에 하나만 쓴다.

## 이유

AX의 게이트가 생기기 전에도 같은 순서와 증거가 필요하다. 다중 에이전트 팀은 20달러 구독의 사용량에 맞지 않는다.

## 대가

P0에 6시간이 늘어난다. 같은 OS 사용자의 위조를 막지 못한다. P1의 병합 게이트 전까지 창업자 확인에 의존한다.

## 다시 검토할 조건

P0이 끝난다. W1-9 게이트를 통과해 AX로 옮긴다. 한 작업에서 절차 시간이 구현 시간보다 길어진다.

## 변경

2026-11-26 (W0-7). 결정은 그대로다. Codex 리뷰를 `bwrap` 래퍼로 연결했다(V-05). 리뷰 입력에 검증 결과와 참고 파일을 더했다. 기준 수정, 작업 취소, 대체 관계, 등록 검사를 더했다. 설계 확인을 명세에도 묶었다. 창업자 편의는 W0-8(2시간)로 나눴다.
