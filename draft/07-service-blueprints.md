# 07. 유형별 팩 요구 사항

**결론: Type A~D는 앞으로 만들 서비스의 요구 조건이다. 지금 개발할 목록이 아니다. 플랫폼은 [13](13-service-lifecycle.md)의 팩 계약으로 이를 수용한다.**

아래 내용은 해당 팩을 활성화할 때 명세의 출발점이 된다. 외부 사실은 그때 다시 확인한다.

## 1. 공통 계약

| 모듈 | 계약 | B | A | C | D |
|---|---|:-:|:-:|:-:|:-:|
| config | 시작 시 환경 변수 스키마 검사 | ● | ● | ● | ● |
| telemetry | 요청 ID, 구조화 로그, 마스킹 | ● | ● | ● | ● |
| health | `/livez`, `/readyz` | ● | ● | 서버 | ● |
| auth | 세션 발급·폐기, OAuth, 매직 링크 | - | ● | 선택 | ● |
| tenancy | 조직, 구성원, RBAC, RLS | - | ● | - | ● |
| billing | 상품, 이벤트, 권리, 대사 | 선택 | ● | IAP | ● |
| privacy | 내보내기, 삭제, 동의 기록 | 선택 | ● | ● | ● |

"10분 안에 생성"(F-23)은 명령 실행부터 새 clone의 설치·시험·빌드 통과까지 잰다. 계정 생성, DNS, 스토어 심사는 뺀다. 패키지 캐시가 있는 상태에서 5회 중앙값을 쓴다.
스캐폴드는 `.ax/template.json`에 템플릿 버전과 파일 해시를 남긴다. 갱신은 3방향 병합 PR로 한다.

## 2. Type B: 유틸리티 웹

- 정적 우선. 서버 계산이 필요할 때만 Worker를 둔다.
- 입력은 기본적으로 브라우저에서 처리한다. 서버로 보내면 크기, 형식, 보존 시간을 화면에 표시한다.
- 남용 제한은 IP 단독이 아니라 경로별 비용과 봇 점수를 함께 쓴다.
- 프로그래매틱 SEO 페이지는 고유 데이터가 있을 때만 색인한다. 빈약한 페이지는 `noindex`다.
- 광고 스크립트는 동의 요건을 확인하고 CSP에 추가한다.
- 성능 목표: 모바일 p75 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하.
- 단건 결제는 선택 능력이다. 쓰면 §3의 결제 규칙을 적용한다.

## 3. Type A: SaaS

핵심 표는 `app_user`, `organization`, `membership`, `invitation`, `product`, `subscription`, `payment_event`, `entitlement`, `audit_log`다.

**격리.** 테넌트 표는 모두 `organization_id NOT NULL`과 RLS를 가진다. 외래 키는 `(organization_id, id)` 복합 키로 테넌트 교차를 막는다.
서비스 역할 키는 RLS를 우회한다. 그래서 웹훅과 관리 작업의 서버 모듈만 쓰고 브라우저 묶음 검사를 CI에 둔다.
기준 DDL은 [`type-a.sql`](schemas/type-a.sql)이다. 격리와 청구의 핵심 8개 표만 담는다. 초대, 상품, 권리, 감사 표는 팩 A를 활성화할 때 더한다. 앱 역할은 표 소유자가 아니다. 열 단위 `UPDATE` 권한으로 테넌트 이동을 막는다.
연결 풀에서는 요청마다 트랜잭션을 열고 `SET LOCAL app.user_id`를 쓴다. 세션 범위 `SET`은 다음 요청으로 새므로 금지한다.
`app.user_id`는 앱 서버가 정한다. SQL 주입이 있으면 공격자가 바꿀 수 있다. 그래서 매개변수 바인딩을 린트로 강제한다.
브라우저가 DB에 직접 접속하는 구성에서는 이 방식을 쓰지 않고 공급자의 서명된 JWT 클레임을 쓴다.
Supabase를 쓰면 `private.uid()`만 `auth.uid()`로 바꾸고 같은 시험을 다시 한다.
CI는 두 조직, 네 역할로 모든 표의 CRUD를 시험한다. 정책 없는 새 표는 실패다.

**결제 웹훅.**
1. 원문 바이트로 공급자가 정한 검증을 한다. 공급자와 이벤트별 방식이 다를 수 있다. 서명이 없는 이벤트는 공급자 API 재조회로 확인한다.
2. `(provider, event_id)` 고유 키로 저장한다. 공급자 ID가 없으면 공식 문서의 식별 필드 조합을 쓴다.
3. 저장을 확정한 뒤 200을 반환한다. 작업자가 `processed_at IS NULL`인 행을 `FOR UPDATE SKIP LOCKED`로 처리한다. 큐 유실이 없다.
4. 처리 때 공급자에서 최신 상태를 조회한다. 이벤트 순서를 믿지 않는다.
5. 구독과 권리를 한 트랜잭션으로 갱신한다.
6. 매시간 최근 변경분, 매일 전체 활성분을 대사한다. 차이는 권리를 자동 회수하지 않고 검토로 보낸다.

금액은 최소 통화 단위 정수와 통화 코드로 저장한다. 원화를 100으로 나누지 않는다.
토스페이먼츠는 빌링키를 발급하고 청구 일정은 가맹점이 구현한다([공식 블로그](https://www.tosspayments.com/blog/articles/dev-subscription-1), 검색 요약으로 확인). 웹훅 서명 방식은 확인하지 못했다.
그래서 청구기를 직접 둔다.
1. `billing_attempt`에 `(subscription_id, period_start, attempt_no)` 고유 키를 둔다.
2. 시도 행을 먼저 확정하고 그 ID를 주문 ID와 멱등 키로 쓴다.
3. 응답을 못 받으면 `unknown`이다. 같은 주문을 조회하기 전에는 다시 청구하지 않는다.
4. 성공한 기간은 부분 고유 인덱스로 한 건만 허용한다.
5. 환불은 시도 상태를 바꾸지 않고 별도 환불 표에 기록한다. 그래서 같은 기간이 다시 청구되지 않는다.
6. 재시도는 최대 3회, 서로 다른 날에 한다. 카드 거절 종류에 따라 즉시 멈춘다.

| 시험 | 기대 |
|---|---|
| 같은 이벤트 10회 동시 | 권리 변경 1회 |
| 해지 후 이전 갱신 이벤트 | 공급자 최신 상태 유지 |
| 저장 직후 프로세스 종료 | 재시작 후 처리 |
| 부분 환불, 분쟁, 결제 실패 | 문서화한 권리 정책 적용 |
| 금액·상품 변조 | 서버 주문 값과 다르면 거부 |

팩 A의 첫 버전은 결제 공급자 하나만 지원한다. 한국 대상이면 토스페이먼츠, 해외 대상이면 Stripe나 대리 판매(MoR) 공급자를 검토한다. 한국 사업자의 Stripe 직접 계정 가능 여부는 공식 자료로 확인하지 못했다. 초안의 "Stripe/토스페이먼츠" 병기는 그대로 확정하지 않는다.

**DB 변경.** 확장 → 이중 쓰기 → 채우기 → 읽기 전환 → 축소 순서다. 축소는 다른 배포로 나눈다. 잠금 시간 제한을 두고 구버전 앱과의 호환을 시험한다.

## 4. Type C: 모바일

- 로컬 DB는 버전과 앞방향 마이그레이션을 가진다. 최근 3개 버전에서 올리는 시험을 한다.
- 동기화 변경에는 `client_mutation_id`, 기준 버전, 삭제 표식을 둔다. 필드별 충돌 정책을 정한다. 돈과 권한은 서버가 정본이다.
- IAP 권리는 서버가 확정한다. 앱의 성공 응답만으로 주지 않는다. 복원, 환불, 가족 공유를 시험한다.
- 토큰은 OS 보안 저장소에 둔다. 앱 묶음에 비밀을 넣지 않는다.
- 푸시 권한은 가치가 드러난 뒤 묻는다. 거부해도 핵심 기능이 동작한다.
- OTA는 네이티브 호환 버전이 같을 때만 쓴다. 단계 배포는 5%, 25%, 100%이며 크래시 없는 세션이 99.5% 미만이면 멈춘다.
- iOS 서명 키는 실행기 또는 빌드 공급자에만 둔다. Linux에서 iOS 빌드는 원격 macOS가 필요하다.

## 5. Type D: 마켓플레이스 팩의 안전 조건

다음을 모두 만족하기 전에는 제3자에게 공개하지 않는다. 사업성 판단은 서비스의 `discover`에서 한다.

1. 판매할 Skill이 실제 작업에서 90일 동안 검증됐다.
2. 제3자 코드를 VM 수준으로 격리하는 시험을 통과했다.
3. 정산, 세금, 환불, 미성년자, 금지 콘텐츠를 전문가와 검토했다.
4. 창업자가 SEV1에 대응할 시간을 확보했다.

1차판은 자체 게시물만 판다. 제3자 게시는 별도 심사다.
패키지는 매니페스트, 권한, SBOM, 서명, 출처 증명, 해시를 가진다. 이름은 재사용하지 않는다. 설치는 권한 차이를 보여 주고 설치 스크립트를 실행하지 않는다. 회수 목록은 실행 때마다 확인하고, 24시간 넘게 갱신하지 못하면 새 실행을 막는다.
공유 커널 컨테이너를 악성 코드의 유일한 경계로 쓰지 않는다.
API 키는 한 번만 보여 주고 해시로 저장한다. 사용량은 요청 ID로 중복을 막고, 선불 잔액을 원자적으로 예약한다.

## 6. 법무 게이트

법률 문서는 초안이다. 게시 전에 다음을 기록한다: 적용 국가, 실제 데이터 흐름과의 일치, 전문가 검토일, 시행일, 이전 버전.
확인할 주제는 통신판매업 신고, 청약 철회, 정기 결제 고지, 개인정보 처리 위탁과 국외 이전, 아동, 부가세다. 이 문서는 적용 여부를 판단하지 않는다.
